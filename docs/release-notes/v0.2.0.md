## WorldHop v0.2.0

This release closes several of the known gaps from v0.1.0: your cloud no longer grows forever, turning on encryption now removes the unencrypted copy, and disconnecting an account ends WorldHop's access at the provider. It also adds protection against a cloud that loses data, changing the encryption passphrase, and cloud version history.

### Please read before upgrading

- **WorldHop now deletes old versions from your cloud storage.** About once a day, after a good sync, it keeps each world's newest 5 versions plus everything from the last 14 days, and deletes the rest along with the data only those versions used. **The first sync after you upgrade can remove a lot of old history** if you have been syncing for a while. Your worlds on your computers and the current version in the cloud are never touched.
  - To keep more history, raise **Snapshots kept in the cloud** on the new **Settings** tab (2 to 50) *before* your first sync after upgrading.
- **S3 users: your access key now needs delete permission** (on AWS, `s3:DeleteObject`), as well as list, read and write. Without it syncing still works but old versions are not cleaned up, and the failure is only written to the log.
- **Encryption users:** once a world's encrypted copy is in place, WorldHop deletes its old unencrypted copy from the cloud. Computers that have not turned encryption on will then report the cloud as having lost their worlds. Turn encryption on there with the same passphrase.

### Gaps fixed

- **Cloud cleanup.** Old versions and unused packs are now removed (see above). It is safe with several computers syncing at once: the current versions are never removed, a version that is still in conflict is kept, a pack is only deleted if no remaining version of any world uses it, and a push re-checks its data right before it finishes. Other computers do not mistake removed history for lost data.
- **Unencrypted copy after turning on encryption.** It is now deleted automatically once the encrypted copy of that world exists. A world that only exists in the cloud keeps its unencrypted copy until a computer that has it syncs.
- **Disconnecting an account now ends WorldHop's access.** Disconnecting Google Drive asks Google to revoke the grant, so WorldHop disappears from your Google account's permissions. If you are offline, WorldHop still disconnects on this computer and tells you to remove it at myaccount.google.com/permissions.
- **Disconnecting S3** forgets the key on this computer and tells you which access key to delete in your storage service. WorldHop cannot cancel S3 keys itself.
- **Cloud data that goes missing or is rolled back** is now noticed. WorldHop stops syncing that world and lets you choose between using the cloud as it is now and uploading this computer's copy. It never repairs or overwrites anything on its own.
- **Changing your encryption passphrase** is now possible: everything is re-encrypted in the background under the new passphrase and other computers are asked for it.

### New

- **Cloud snapshots:** the cloud keeps a version history of each world. Browse it under **Snapshots > In the cloud** and restore an older version (the current world is saved as a local snapshot first).
- **Settings tab** with the number of versions kept in the cloud.
- A clearer page in the browser after Google sign-in, showing what happened and what to do if it failed.
- The update check follows the repository rename, so "Update available" works again.
